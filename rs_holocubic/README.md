# HoloCubic 控制台

Rust / egui 原生桌面工具。左侧切换主页、沙漏、文字、图片、AI 雷达和日历。全部通过 USB 控制 ESP32-S3 屏幕；主页支持设备本地轮播。设备不需要互联网，AI 雷达的数据采集需要电脑访问公共雷达网站，日历只读本地 CalendarTask 数据。

## Rust USB

全部 GUI 后台动作（ports/status/hello、clear/text/image/task、雷达、日历、主页）走进程内 `protocol.rs` + `usb.rs` + `actions.rs` + `render.rs`。帧格式仍为 `@HCUSB/1 ` + JSON + `
`，CRC32 为 8 位小写十六进制。

## 运行

环境：Windows、Rust 1.88+。单 EXE 分发，不需要 Python / Pillow / pyserial。

```powershell
cargo run
# 正式构建
cargo build --release
```

启动后选择 COM 口或自动识别，点击“检测连接”。需将上级 `device_app/` 的 Lua 上传到设备 `/sd/apps/usb_display/`，然后重启 USB Display 应用。

## 模式

- **主页**：勾选要轮播的沙漏、雷达、文字、图片、日历，设置各页完整停留时间，点击“应用轮播”。内容在对应编辑页设置。
- **沙漏**：底部居中的任务名称、时分秒、初始剩余百分比、顶部说明、强调色。百分比固定显示两位小数，`72.35%` 在 USB 中表示为整数 `7235`。
- **按时间递减**：从初始百分比随完整任务时长递减到 `0.00%`。
- **手动百分比**：沙量保持指定值，倒计时独立运行。
- **循环**：默认不勾选；勾选并点击“应用并开始”后，每轮结束立即恢复设定时长及初始百分比，累计秒数从零开始。暂停会同时暂停循环，重置从新一轮开始；不勾选则结束后停止。两端各自处理循环，不增加 USB 查询或图片传输。
- **应用并开始**：上传本次任务的静态中文标签并开始新任务。暂停、继续和重置发送小型状态命令；停止返回等待界面。
- **文字**：中文标题、正文、底部说明、强调色，由 Rust 渲染后发送 JPEG。
- **图片**：选择本地 PNG/JPEG/BMP/WebP，等比适配到 320×240；可独立加载预览。

沙漏右侧为“任务运行画面”：启动、暂停、继续、重置或手动检测时读取一次设备状态，之后电脑与 ESP32 按同一份任务参数分别计算百分比、倒计时、累计秒数及动画。标题和说明仍使用设备确认的 JPEG 字节，不从未发送的编辑草稿猜测。修改草稿后，点击“应用并开始”且收到设备确认才切换任务。

**没有自动轮询，也没有定时校准。** 桌面使用单调时钟，从最近确认的快照推算经过时间；定时百分比与设备一样使用 `initial_bp × 剩余秒数 / 总秒数` 和 float32 舍入，保留两位小数，不按画面帧数扣减时间。暂停、完成停止计时；USB 未连接或操作失败时，电脑仍按上次参数独立运行，不因没有回执而冻结。

“检测连接”是一次性的校准操作；连接标志仅代表最近一次通信结果，不检测实时拔插。设备断电、外部程序修改任务、系统休眠或长时间时钟漂移后，可手动检测重新校准。传输延迟、两端时钟及字体栅格化可能有细微差别；这不是逐帧像素截图。

文字、图片模式仍为未发送的编辑预览。`ELAPSED` 是任务累计计时秒数，并非外部业务计数或 Codex 请求次数。

## 数据与边界

- 内容草稿通过“保存配置”写入 EXE 同目录的 `holocubic_settings.json`；主页勾选和时长每次变化后自动写入同目录 `home_settings.json`，下次启动恢复，无需手动保存。保存失败会在主页提示；不保存账号凭据。
- USB 工作在线程中串行执行；失败提示保留编辑内容，不会自动刷机或复位。
- 中文标签通过一张稀疏 JPEG 在应用任务时上传一次；后续动画由 LVGL 本地完成，不逐帧传图、不持续写卡。
- 沙漏背景为纯黑 `#000000`，设备容器、中文标签背景和桌面画面一致，适合棱镜透明显示。
- 设备提供 `mirror_protocol=1`，任务状态包含 `initial_bp` 和 `timed`，中途接入不从已四舍五入的百分比反推原始值。标签仅在首次连接或 CRC 改变时按 192 字节分块回读，CRC32 校验失败不会显示假预览。切换串口会清空旧画面缓存。
- 循环模式要求设备提供 `loop_protocol=1`，任务指令和状态都明确携带布尔字段 `looping`。首次升级需更新两个 Lua 文件；当前本地配置新增 `looping=false`，其余已保存草稿保留。
- 界面关闭后，已启动的任务在屏幕上继续；设备断电后仍需从 Launcher 启动 USB Display，再应用任务。
- 同时只允许一个程序操作设备串口；VMware 不应接管 `USB JTAG/serial debug unit`。
- 不会读取真实 Codex 额度、设置开机自启或更改网络安全设置；雷达只读本机 Codex/CC Switch SQLite 记录，不修改源数据库。

## 主页轮播与渐变

可用 `--home` 直接打开主页。默认勾选沙漏与雷达、各停留15秒，文字和图片按需勾选；每页可设1～3600秒，按主页列表顺序循环。

- 停留时间不含1.2秒平滑淡出/淡入：旧画面缓慢淡至黑底，中点换页，再淡入新画面；单独选择一页时不执行自切换。设备以20ms间隔更新透明度，控制台使用同一缓动曲线。
- 应用时预加载各画面一次。之后轮播由设备本地时钟执行，关闭控制台或断开USB数据连接后仍继续（需保持供电）；设备重启后需要重新应用。
- 沙漏跨页保持独立计时，不在每次轮到时重启；“停止轮播”保留当前画面，方形停止按钮则清屏。开始新的轮播会采用内容编辑页的任务配置。
- 文字和图片各通过一次 JPEG 上传存为独立素材；轮播期间只改变显示内容，不重复上传、不循环写卡。雷达仍按5秒更新，后台更新不会中断轮播。
- 预览使用设备确认的轮播列表、相位、沙漏/雷达状态和CRC素材。检测连接后按需回读，后续本地推算；分块传输耗时会补偿到预览时钟，不增加周期性状态查询。
- 固件串口输出长JSON曾出现截断，因此大于384字节的回执改用短元数据加96字节 `response_read` 拉取并核验CRC；电脑端会保留未收完的一行，不把半行当完整JSON丢弃。
- 更新切换动效时可从已校验的任务检查点恢复原时长、百分比基准、累计进度和暂停状态；不会把剩余时间当成新的完整周期。

### 拍击能力核查

当前[官方 Lua 接口文档](https://github.com/clocteck/holocubic-apps/blob/main/README_LUA.md)只公开 IMU 的 roll/pitch 姿态事件，gx/gy/gz 为预留值，通常为0；未公开单拍/双拍事件或原始加速度读取。本版本不启用拍击识别，也不把晃动近似当成拍击重置任务。可靠接入“单拍暂停/继续、双拍重置”需要固件进一步开放拍击或传感器数据；这不等同于认定硬件没有传感器。

## 日历清单

左侧选择“日历”，或运行 `rs_holocubic.exe --calendar`。默认读取本机当天、CalendarTask 当前选中的子日历；不跟随原应用正在浏览的历史日期。点击“应用到屏幕”启用显示与后续变化同步，也可以在主页勾选“日历”加入轮播（默认不替用户勾选）。

- 数据位置：`%APPDATA%/CalendarTask/Db/calendar.db`，与[日历清单官方数据文件说明](https://help.xdiarys.com/?p=626)一致。通过 SQLite `mode=ro` 与 `query_only` 读取，不更新原库或任务完成状态，不读取账号凭据。
- 数据口径：读取当前子日历/团队对应的 `item_table` 当日日格 `dkcal_mdays_YYYYMMDD`，保留文本顺序。没有跨日补录或从历史、倒数日、订阅表中猜测任务；如出现重复日格，明确报错而不擅自合并。
- 完成显示：识别行首 `[+]`，移除颜色字体包装；完成项显示灰色删除线，正文中间的 `[+]` 不改变完成状态。序号、中文内容、日期与完成数同时显示；完成操作仍在原日历清单中进行。
- 更新策略：页面可见或已启用日历同步时每5秒读取，内容签名不含采集时间，所以内容未变不传图。正常运行跨零点会读取新的一天；控制台关闭后设备保留带明确日期的最后数据，不会假装更新到新日期。
- 页面策略：正文14像素、行高18像素、条目间隔6像素；按用户要求只显示第一页，不建立自动翻页定时器。超出首页容量时页脚提示“还有内容”，控制台左侧仍显示完整清单。
- USB 策略：在非活动 A/B 槽上传首页，CRC校验完成才原子替换；未上传完整的新内容不会覆盖旧画面。预览回读实际页面，按签名复用缓存。

测试：`lua test_calendar_scene.lua`、`cargo test --locked`。日历采集与渲染由 Rust 单测覆盖。

## AI 雷达

左侧选择“AI 雷达”，也可用 `rs_holocubic.exe --radar` 直接打开。控制台沿用沙漏的“左侧设置 / 右侧设备运行画面”，不再显示另一套桌面图表。页面可见或 USB 雷达同步启用时每 5 秒尝试采集，前次未结束不叠加；预览使用与设备相同的400ms缓动、布局和统计口径。

- **屏幕左侧评分卡**：本机最近 10 个用户主任务，各取最新 `turn_context` 的模型和强度，排除子代理、自动任务；同档位合并计数。日志增量读取，只提取模型和强度，不上传本机记录。缺失评分显示 `--`，强度未知时只显示模型名。
- **评分来源**：只读取 [AI 雷达](https://codex-reset-radar.pages.dev/)的[软件编码接口](https://codex-reset-radar.pages.dev/api/intelligence-efficiency-metrics)，不再采集或混合视觉空间分数。分数、费用和耗时均为第三方编码测试参考，不是这些任务的质量评价或账单；左侧设置栏提供来源入口与采集时间。实测分不保证随强度单调增加，不人为调整 medium/max 的高低。
- **屏幕右侧图表**：只读 `~/.cc-switch/cc-switch.db` 的 `proxy_request_logs`，滚动 24 小时内 `app_type=codex`、`data_source=proxy`、HTTP 2xx 且无错误的记录。采集15分钟分桶后统一合并为24个小时桶，显示前三模型与 Other；饼图按成功请求次数计算。包含自动审查，不计会话导入，不拿 Token/费用为零推断免费使用。不将代理 session_id 强行关联到左侧任务。
- **模型归属**：采用 CC Switch 的 `model` 字段，而不是客户端别名或计价模型。此字段可能来自上游响应或映射后的出站模型，语义见 [CC Switch 源码](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/proxy/response_processor.rs)；不能据此鉴别供应商后台权重。
- **右侧强度**：当前 CC Switch 的代理表没有推理强度字段，因此不显示强度，也不显示“未记录 / NOT LOGGED”占位文字。不能用左侧任务配置反推全部代理请求的强度。
- **底部重置雷达**：只提取网站全局重置预告、预计时间、来源和确认提示；过了预计时间仅显示“等待确认”，不推断重置完成，不执行兑换或重置，也不展示个人额度。
- **缓存与错误**：公共网站遵循 HTTP 缓存期限并支持条件请求，不强刷上游；本机统计仍每 5 秒更新。派生缓存位于 exe 旁的 `radar_cache/`。网站返回陈旧数据、网络失败或本地数据库不可读时明确提示；各区域独立失败，不捏造零分或零用量。
- **只读边界**：不读取账号密钥，不修改 Codex/CC Switch 数据库，不启动 Codex 任务；与 USB 工作线程独立，不增加沙漏轮询。

### USB 雷达模式

检测连接后点击“应用到屏幕”切换设备；仅打开页面不改变屏幕。启用后每 5 秒发送最新统计，慢连接只保留最新待发数据，不堆积。切走编辑页仍同步；应用沙漏、文字、图片或停止显示会关闭雷达同步。点击“停止同步”保留设备最后数据；关闭应用或断开 USB 后也不再更新，设备超过 15 秒显示 `STALE`。

设备需更新 `../device_app/main.lua` 和新增的 `../device_app/radar_scene.lua`。使用已有热点开发接口部署一次，日常更新只走 USB；不刷固件。桌面仍需联网读取公共评分/重置网站，设备不需联网。

- 320×240 纯黑原生 LVGL 页面：左侧两张编码卡，每 6 秒轮播下一组（最多十组模型/强度组合）；右侧 24h 请求总数、趋势和分段环形占比，底部重置预告状态。
- 小屏使用已验证的 ASCII 字体，预览使用同源 Montserrat；完整公告通过控制台来源入口查看。Other 汇总全部剩余模型，不丢计数；设备和预览都使用同一组24个小时桶，不在预览端重新统计。
- `radar_begin/chunk/end`：最多 8KB JSON，在 RAM 中按 96 字节分块收齐并验证 CRC32 后提交。数值使用有界整数，CRC 使用十六进制字符串，不传 Unix 时间大数。协议校验失败不会发布半帧，不传 JPEG、不写 SD。
- 设备本地 400ms 微动画，稳定后仅每秒更新年龄和倒计时；公开数据失败时显示 `SOURCE WARN`，缺失计数/分数不显示成零。预计窗口结束只提示查看确认，不声明已经重置。
- **真实预览**：发送成功直接复用已确认快照；手动检测时通过 `radar_read` 分块回读设备 RAM，并验证 CRC。CRC 相同则复用缓存。回执的 `scene_seconds` 和 `age` 校准轮播/倒计时，之后两端独立运行，不增加周期性状态查询。未回读时留空；本机新采集不能覆盖设备预览；切换串口清除旧设备缓存。

附加测试：安装 Lua 5.3+ 后运行 `lua test_radar_scene.lua`；Rust 侧 `radar_data` / USB 单测见 `cargo test --locked`。

验证命令：`cargo test --locked`、`cargo clippy --all-targets -- -D warnings`。使用 `--radar --screenshot <绝对路径.png>` 会只读连接 USB、回读设备实际雷达画面并截图；不会应用待发数据或启动持续同步。

## 应用图标

使用用户提供的棱镜小电视 PNG，源图保存在 [assets/holocubic-icon.png](assets/holocubic-icon.png)，保留透明背景，原始文件未改动。
